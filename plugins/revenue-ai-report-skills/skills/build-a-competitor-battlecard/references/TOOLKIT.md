# Battlecard Toolkit: Deal Evidence, Row Sourcing, Objection Answers, and the Live Test

**Use this file when:**
- You are about to build or rebuild a card for one competitor and need the evidence sheets, not just the prompt.
- Reps are giving five different answers to the same objection and you need one sourced version.
- A competitor just shipped or changed pricing and you need to know which lines to change, not rewrite the card.
- An existing card is undated, unowned, or ignored and you need to decide what survives.

The SKILL.md holds the logic. This file holds the instruments. Run them in the order below.

---

## 1. The Build Sequence

| Step | What you do | Output | Time (rule of thumb) |
|---|---|---|---|
| 1 | Confirm a sourced competitor profile exists | Profile with a source per fact | 0 min if it exists; otherwise run a competitor research pass first |
| 2 | Pull five recent deals against them | Deal evidence log (Section 3) | 20-30 min |
| 3 | Pick the six capabilities buyers actually raise | Capability tally | 10 min |
| 4 | Draft the card with the Quick prompt | Draft card | 10 min |
| 5 | Grade every row's source; cut what fails | Sourced card | 15 min |
| 6 | Send own-product claims to their owner | Signed fact sheet | 1-3 days elapsed, 10 min of work |
| 7 | Write the avoid ground and the redirect | Avoid section | 10 min |
| 8 | Test in three live deals, then correct | Version 1.1 | 2-4 weeks elapsed |

## 2. Data Checklist

| What | Where (system category) | How far back | Watch for |
|---|---|---|---|
| Closed deals where this competitor was present | CRM competitor field on opportunities | 2-4 quarters | Field often blank. Also search notes and call transcripts for the name |
| Buyer's stated reason for the decision | Loss and win interviews, closing emails, call recorder (final calls) | Same deals | Rep-written loss reasons are the rep's view, not the buyer's |
| Capabilities buyers raised | Call recorder transcripts, RFPs, evaluation scorecards buyers shared | Same deals | Count only what the buyer raised, not what the rep demoed |
| Competitor pricing and packaging | Their public pricing page, public quotes buyers shared, procurement documents | Current, dated | Buyer-shared quotes may be confidential. Use the fact, not the document |
| Competitor capability facts | Their docs, release notes, public review sites, buyer statements | Last 2 releases | Their marketing claims are claims, not facts |
| Your own capability and pricing facts | Product and pricing owners, current documentation | Current | Never from the model or memory |
| Open deals with this competitor | CRM | Now | These are your three live test deals |

**Minimum mix (SKILL.md input):** three losses and two wins. If you cannot find five, the card is premature. Ship a one-page "what we know" note instead and mark it draft.

## 3. Step 2: The Deal Evidence Log

| Deal | Outcome | Size / segment | Buyer's stated reason (verbatim) | Rep's stated reason | Source of buyer reason | Capabilities the buyer raised |
|---|---|---|---|---|---|---|
| L1 | Lost | | | | | |
| L2 | Lost | | | | | |
| L3 | Lost | | | | | |
| W1 | Won | | | | | |
| W2 | Won | | | | | |

### Reading the log

| Pattern | Meaning | Card effect |
|---|---|---|
| Buyer reason and rep reason differ | The rep reason is a story | Use the buyer reason only |
| Same buyer reason in 2+ losses | A real loss pattern | Becomes avoid ground or an objection |
| Win reason the buyer raised unprompted in 2+ wins | A real win reason | Goes on the card |
| Win reason only the rep mentions | Not a win reason (SKILL.md rule) | Cut |
| Loss reason is price in every loss | Often a value or qualification gap, sometimes truly price | Check deal size and segment before writing a price answer |

## 4. Steps 3 and 5: Capability Selection and Row Sourcing

### Capability tally

List every capability raised by any buyer across the five deals. Count deals, not mentions. Keep the top six.

| Capability | Deals raised in | Raised by buyer or rep? | Keep? |
|---|---|---|---|

### Comparison scale

Use words, not checkmarks. A checkmark hides the difference that decides the deal.

| Rating | Meaning |
|---|---|
| **Ahead** | We do it and they do not, or ours is measurably better on a dimension the buyer named |
| **Parity** | Both do it well enough for this buyer. Do not argue it |
| **Behind** | They are better. Say so on the card |
| **Different** | Both solve it in ways that suit different buyers. Name which buyer suits which |

### Source grades per row

| Grade | Source | Ships? |
|---|---|---|
| **P** | Public source with a URL and a checked date (their docs, pricing page, release notes) | Yes |
| **B** | Buyer statement with deal ID (call, email, interview) | Yes |
| **O** | Own-product fact confirmed by its owner, with name and date | Yes (our rows only) |
| **T** | Thin: one buyer statement only, or a public source older than two releases | Yes, flagged "thin" on the card |
| **X** | Memory, rumor, rep opinion, model output, or the competitor's marketing claim alone | No (SKILL.md rule) |

**Contradiction rule (from SKILL.md):** if two of the five deals contradict a line, cut it.

## 5. Objection Answers

### The answer pattern

| Part | What it does | Length |
|---|---|---|
| 1. Acknowledge | Says what is true in the objection | One sentence |
| 2. Fact | The sourced fact that changes the picture | One sentence, with source code on the card |
| 3. Question | Hands the decision back to the buyer's criteria | One question |
| 4. Proof (optional) | Customer result or demo moment | One line |

**Rule of thumb:** 40 words or fewer. A rep must be able to say it from memory. If the honest answer is "they are right," the answer is the avoid-ground redirect.

### Answer quality check

| Test | Fail looks like |
|---|---|
| Starts by agreeing with something true | "That's not accurate" as the first words |
| Contains a checkable fact | Adjectives only ("much more robust") |
| Does not attack the competitor | "Their product is buggy" |
| Ends with a question about the buyer | Ends with a pitch |
| Would survive the competitor reading it | Claim from a rumor |

### Discovery questions that expose a real gap

| Good question | Why it works | Bad version | Why it fails |
|---|---|---|---|
| Asks how the buyer will do a task we are Ahead on | Buyer discovers the gap themselves | "Did you know they can't do X?" | Sounds like a trap and invites a fact-check |
| Asks about a scenario that happens in the buyer's business | Grounded in their reality | Hypothetical edge case | Buyer dismisses it |
| Neutral wording | Holds up if the buyer repeats it to the competitor | Loaded wording | Damages trust when repeated |

## 6. The Card Template (one page, ready to fill)

```
BATTLECARD: [Us] vs [Competitor]
Owner: [name]   Last checked: [date]   Refresh: [cadence]   Version: [x.y]

WHEN YOU MEET THEM
[One line: what kind of buyer they usually show up with, from the deal log]

CAPABILITY COMPARISON (six buyers actually raise)
| Capability | Us | Them | Rating | Source |
|---|---|---|---|---|

WHERE WE WIN (five, each tied to a deal)
1. [Situation] because [reason]. [Deal ID]

WHERE THEY WIN: DO NOT FIGHT HERE (three)
1. [Situation]. Instead: [what the rep does: reframe, qualify out, change the evaluation criterion]

OBJECTIONS AND ANSWERS (five)
"[Objection, in buyer words]"
  Acknowledge: / Fact (source): / Question:

QUESTIONS TO ASK (three)
1. [Question] Exposes: [gap]

PRICING NOTES
[Only sourced facts. Their list structure, our structure, how to frame the difference]

THIN ROWS (flagged)
[Any row graded T, and what would firm it up]
```

## 7. Step 8: The Live Test

| What to log per deal | Why |
|---|---|
| Which card lines the rep used | Finds dead lines |
| Buyer reaction to each answer (accepted, pushed back, ignored) | Finds weak answers |
| Objections heard that are not on the card | Finds gaps |
| Any fact the buyer corrected | Finds wrong rows. Fix within 48 hours |

| After three deals | Action |
|---|---|
| A line never used | Cut or move to a back page |
| An answer pushed back on twice | Rewrite or move the topic to avoid ground |
| A new objection heard twice | Add it |
| A fact corrected once | Re-source it now |

### Refresh triggers

| Trigger | Action |
|---|---|
| Competitor release or pricing change | Change the affected lines only. Re-date them. Notify owners of open deals with this competitor |
| Two new losses with a new stated reason | Re-run the deal log |
| Our release changes a rating | Owner re-confirms; update rating |
| 90 days with no change (rule of thumb) | Re-check every P-graded source |

## 8. Worked Example: Acme vs Competitor C

*Illustrative only. Acme is a fictional 400-person B2B software company selling quoting and pricing software to mid-market sales teams. Competitor C, all deals, and all facts are invented.*

### Deal evidence log

| Deal | Outcome | Buyer's stated reason | Rep's stated reason | Source |
|---|---|---|---|---|
| L1 | Lost | "We needed to be live before the price increase on the 1st. They could do it in three weeks." | Price | Closing email |
| L2 | Lost | "Your approval workflows looked more powerful, but our team only needs two steps." | Feature gap | Loss interview |
| L3 | Lost | "Setup time. We don't have an admin." | Price | Call recording, final call |
| W1 | Won | "Your approvals handle our discount rules across three regions." | Relationship | Win interview |
| W2 | Won | "Their quotes couldn't pull usage data from our billing system." | Better demo | Call recording |

**Reasoning:** reps said "price" twice; buyers said speed or simplicity three times. The real loss pattern is setup speed for simple buyers, not price. Wins came from complex approval rules and billing data, both raised by buyers unprompted.

### Capability tally (top six)

| Capability | Deals raised | Rating | Source |
|---|---|---|---|
| Time to go live | 4 | Behind | B (L1, L3, W1, W2), P (their onboarding page, checked 2026-09-22) |
| Multi-step approval rules | 3 | Ahead | B (W1, L2, W2), O (product lead, 2026-09-20) |
| Pulling usage data from billing | 2 | Ahead | B (W2, L1), O (product lead) |
| Ease for a team without an admin | 3 | Behind | B (L2, L3, L1) |
| Quote document templates | 2 | Parity | B (L2, W1), P (their docs) |
| Price for under 25 seats | 2 | Different | B (L1, L3), P (their pricing page), O (pricing lead) |

### Card (extract)

**Where they win: do not fight here**
1. Simple pricing, single region, no admin, needs to be live in under a month. **Instead:** say so, ask about the next 12 months (new regions, usage pricing). If neither is planned, qualify out early and save the cycle.

**Objection:** "We heard you take months to set up."
- Acknowledge: "Setup is longer than simpler tools; it's typically six to eight weeks."
- Fact (O, onboarding lead, 2026-09-18): "Most of that time is building your approval and discount rules, which is the part buyers say they needed."
- Question: "How many approval steps and regions will your quotes need by next year?"

**Question to ask:** "Walk me through how a quote with a usage-based line gets priced today." Exposes: billing data gap (W2).

### What the live test changed

| Deal | Finding | Change |
|---|---|---|
| Live 1 | Buyer asked about integration with their contract tool; not on card | Added as a seventh capability on the back page, graded T |
| Live 2 | Setup answer accepted; buyer moved to approval rules | No change |
| Live 3 | Rep used "they can't handle usage pricing"; buyer said the competitor had shipped it | Re-sourced: competitor release two weeks earlier. Rating changed from Ahead to Parity for basic usage lines, Ahead remains for usage pulled from billing. Line re-dated |

## 9. Decision Table and Red Flags

| If you see | It means | Do this |
|---|---|---|
| Every rating is Ahead or Parity | The card is a brochure | Add the honest Behind rows. Reps will not trust it otherwise |
| Win reasons with no deal ID | Wishful thinking | Cut until a deal supports them |
| Rep loss reasons are all "price" | Weak loss data | Pull buyer statements from calls and interviews |
| A row sourced only to the competitor's website marketing | Their claim, not a fact | Grade X unless confirmed by docs or a buyer |
| You need a different card per deal | Positioning problem (SKILL.md limitation) | Escalate to positioning work |
| Card older than one competitor release | Probably wrong somewhere | Re-check P rows before the next deal |
| Reps quote lines that are not on the card | The card misses the real conversation | Run the live test and add them |

## 10. AI Assist: Splitting the Work

| Task | AI assistant | Human |
|---|---|---|
| Extract buyer reasons from transcripts and emails | Yes, with a verbatim quote and timestamp per reason | Spot-check every quote |
| Tally capabilities raised | Yes | Confirm buyer vs rep attribution |
| Draft the card | Yes, from pasted material only | Grade every row's source |
| Our own product facts | Never | Product or pricing owner confirms |
| Competitor facts | Only from pasted, dated sources | Checks each URL is current |
| Objection answers | Drafts in the four-part pattern | Says each one aloud; cuts anything a rep would not say |

### Follow-up prompts after the Quick prompt

1. "For each of the five deals, extract the buyer's stated reason as a verbatim quote with its source, and separately the rep's stated reason. Mark where they differ."
2. "Count how many deals each capability was raised in by the buyer, not the rep. Keep the top six and show the count."
3. "Add a source column to every row on the card. Use P for a public dated source, B for a buyer statement with deal ID, O for our owner-confirmed fact, T for thin. Mark any row you cannot source as X and remove it."
4. "Rewrite each objection answer as: one sentence acknowledging what is true, one sourced fact, one question about the buyer's needs. Maximum 40 words each."
5. "For each 'where they win' item, write what the rep should do instead: reframe, change the evaluation criterion, or qualify out. Do not argue the point."
6. "List every fact on this card that did not come from the pasted material. If none, say none."

### Errors this job invites, and how to check

| AI error | How to spot it | Fix |
|---|---|---|
| Writes competitor features from training data | Row has no source, or the source is not in your paste | Run follow-up prompt 6; cut |
| Invents customer names or outcomes | A named customer you did not supply | Delete. Never ship |
| Uses the rep's reason as the buyer's | Loss reasons read "price" | Run follow-up prompt 1 |
| No honest avoid ground | "Where they win" is soft or empty | SKILL.md rule: name at least one area they are better |
| Answers that attack | Words like "buggy," "outdated," "struggle" | Apply the "would survive the competitor reading it" test |
| Overconfident ratings | All Ahead on thin evidence | Require two sources for Ahead, rule of thumb |

## 11. Common Mistakes

| Mistake | How to spot it | Fix |
|---|---|---|
| Building from memory or an old deck | No deal IDs or source dates | Start from the deal log |
| Comparing 20 capabilities | Card runs to three pages | Six buyers raise. The rest goes to a back page or nowhere |
| Product marketing writes it alone | Reps never used it | Include two reps in drafting and the live test |
| No owner or date | "Who updated this?" | Owner and last-checked date at the top, always |
| Rewriting the whole card on every change | Approved answers get lost | Change the affected lines only |
| Telling reps to fight on lost ground | Repeated losses on the same reason | Avoid ground with a redirect |

## 12. The 5-Minute Version

For a rep with a call in ten minutes and no card.

1. Ask the deal team: "Last time we lost to them, what did the buyer say?" Write it down verbatim.
2. Write one place you win, with the deal it happened in.
3. Write one place they win and what you will do instead.
4. Write one question that lets the buyer find your strength.
5. State nothing about their product you cannot source. Say "I'd rather you ask them" instead.

## 13. The Deep Version

For a top-three competitor, a new entrant taking share, or a board-visible win rate problem.

| Addition | What it adds |
|---|---|
| 15-20 deals instead of five, split by segment | A card per segment where the win pattern differs |
| Loss interviews run by someone other than the rep | Honest buyer reasons |
| Win rate against this competitor by segment, from CRM, quarterly | Shows whether the card changed outcomes |
| Monitored source list (their pricing page, release notes, docs) with a named owner | Changes reach the card within days |
| Diff-based updates pushed to owners of open deals with this competitor | Reps get changed lines, not a new document |
| Quarterly review with product on every Behind row | Turns avoid ground into roadmap input |
