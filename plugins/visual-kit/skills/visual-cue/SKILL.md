# Visual Cue

Prose is the default; a visual earns its place only when it makes a point graspable faster than a sentence can. This skill is the **detector**: while you write or edit, it watches for text that is secretly a picture, and routes it to the family that draws it. It does not render anything itself.

## The one test

For the passage in front of you, try to finish this sentence with a verb:

> "After seeing one visual here, the reader should understand that ______."

If you can write it, a visual is probably warranted, and that sentence becomes the figure's title/caption. If you can't, keep it as prose.

## Cues in the text -> family

| What the prose is doing (signals) | The claim | Route to |
|---|---|---|
| "X vs Y", "more/less than", "compared to", parallel numbers | comparison / magnitude | **visual-data-charts** |
| "grew", "declined", "over the last N quarters", a trend, dates | change over time | **visual-data-charts** |
| "made up of", "breaks down into", "driven by", "X = a + b + c" | composition / drivers | **visual-data-charts** |
| "first... then... next", numbered steps, "hands off to" | sequence / ownership | **visual-process-maps** |
| "on one hand / on the other", "tradeoff", "we could A, B, or C" | choice / tension | **visual-strategy-diagrams** |
| "reinforces", "compounds", "the more X the more Y", "flywheel" | reinforcing loop | **visual-strategy-diagrams** |
| "from the old way to the new way", "before/after", "the shift" | transition | **visual-strategy-diagrams** |
| market size, competitors, positioning, ICP, buyer, funnel, pipeline | GTM | **visual-gtm-market** |
| agents, model stack, data flow, governance, autonomy, AI maturity | AI system | **visual-ai-systems** |
| a big proof number, a quote, a case, "why now", a metaphor, a hero claim | narrative / proof | **visual-storytelling** |
| three-plus parallel items you're about to bullet | parallel set | **visual-storytelling** or the matching family |

## Route, don't render

Once you have named the claim and the family, hand off to that spoke. The spoke selects the exact form and calls **visual-master** to build it. If several claims hide in one paragraph, that is several visuals - or split the paragraph. One visual, one claim.

## Leave it as text when

- The point is a single fact or a short assertion - a hero sentence beats a chart.
- The relationship is trivial (two numbers, one comparison) - say it in words.
- You would have to invent data to fill the visual - never fake it; say the numbers in prose or ask for the point.
- The document is already visual-dense - more pictures reduce clarity. Aim for a rhythm of prose and figures, not a gallery.

## In documents specifically

A visual in a report is a **figure + a caption that states the takeaway**, not decoration. Put the claim in the caption ("Conversion, not volume, is the Q4 constraint"), keep one focal point, and reference it from the surrounding text. In newsletters and posts, one strong visual usually beats three weak ones.
